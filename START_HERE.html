La différence essentielle

Pas de relais. Pas de base. Pas d’envoi automatique.

Le membre vérifie son membership et réclame un avantage. Il saisit ses coordonnées en mémoire dans la page. Son wallet signe uniquement une empreinte cryptographique salée, sans recevoir le nom, le courriel ou le sel en clair.

Puis le membre choisit de copier sa demande privée. La copie place le contenu dans le presse-papiers de son appareil et efface les champs/références de la page. Il colle ensuite la demande dans sa propre messagerie et l’envoie. Le lien de messagerie fourni ne contient aucun corps prérempli.

Les extensions, le wallet, le navigateur, l’appareil et sa messagerie restent des frontières de confiance. Effacer la page ne purge ni la mémoire physique, ni le presse-papiers, ni les brouillons ou sauvegardes. Le reçu signé n’est pas chiffré ; gardez-le privé.

Politique technique détaillée · Notice membre · Émission manuelle et doublons

01 — PUBLIER LE CODE

Via le site web GitHub.

  1. Décompressez le ZIP. Ouvrez agi-club-entitlement-registry.
  2. Sur GitHub, créez un dépôt appartenant à MontrealAI, nommé agi-club-entitlement-registry. N’ajoutez pas de README, de licence ni de gitignore généré : ils sont déjà fournis.
  3. Choisissez uploading an existing file ou Add file → Upload files. Téléversez le contenu de ce dossier, pas le ZIP ni un second dossier englobant.
  4. Affichez les fichiers cachés sur votre ordinateur et incluez .github, .gitignore, .nvmrc, .npmrc, .env.example. Le guide donne un repli par l’éditeur web.
  5. Limite documentée : 100 fichiers par téléversement, 25 MiB par fichier. Au-delà de 100 fichiers, utilisez deux lots. Vérifiez que README.md, package.json et contracts apparaissent directement à la racine.

Le fichier .gitignore n’est pas une protection suffisante contre un téléversement manuel erroné. Partez d’une extraction neuve et inspectez la liste avant de confirmer.

02 — DÉPENDANCES ET QUALIFICATION

Un vrai build, pas un indicateur de démonstration.

Le dépôt contient maintenant un package-lock.json généré par npm. Utilisez ce fichier pour une installation reproductible et lancez directement le workflow 02 — Build and qualify. Le workflow 01 est réservé aux anciennes extractions sans lockfile ; il refuse d’écraser un fichier existant.

Le workflow 02 — Build and qualify tente ensuite les contrôles locaux, sans jamais déployer Ethereum. Sur un ordinateur équipé de Node 22.16+ et npm 10 :

npm ci --ignore-scripts --no-audit --no-fund
npm audit --audit-level=high
npm run qualify

Les dépendances sont installées à partir du lockfile validé. Un module absent n’est jamais remplacé par la cryptographie fictive des tests. Le front-end publiable est produit par npm run build:site dans dist/site.

03 — AUTORISER PUIS DÉPLOYER

Le détenteur de club.agi.eth garde la décision.

La procédure Hardhat sépare les essais locaux, le fork mainnet en lecture seule, la revue indépendante, l’approbation du bytecode exact, le déploiement limité et l’ouverture large.

Une clé de déploiement dédiée peut être distincte du wallet racine. Ne mettez jamais la phrase de récupération du Ledger/Safe dans un fichier ou GitHub. Le déployeur n’obtient aucun droit spécial.

ENGLISH QUICK START

Static UI. Public entitlement proof. Private manual fulfilment.

Upload the extracted repository contents to MontrealAI/agi-club-entitlement-registry, including dotfiles. Use the committed package-lock.json for a clean installation and inspect workflow 02's real build/test results. Workflow 01 is only for a source extraction without a lock. Read the complete English Hardhat guide before any deployment.

No mail relay, private database, analytics, contact persistence or automatic email is included. The wallet signs a salted contact commitment, not plaintext recipient details. Copying the private receipt is explicit and uses the device clipboard. Email and Eventbrite are separate user/organizer actions. This source candidate has no independent audit or mainnet authorization.
