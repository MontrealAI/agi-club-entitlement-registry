# Contributing

Use pull requests, exact dependency versions and the reviewed lock. Run offline tests and then the full qualification pipeline. Preserve failures and disclose unexecuted checks.

Do not add contact persistence, automatic forwarding, telemetry, analytics, recipient-bearing URLs or a mail relay to this static edition. A future change in privacy architecture needs an explicit product/privacy review and a new compatibility policy.

Never publish real receipts, contact lists, private deployment approvals, `.env` or keys in commits/issues/logs/artifacts. Examples must use clearly fictitious people and example.org addresses.

Do not change the immutable production ENS authority or reuse an entitlement ID for a different benefit. Contract changes require separate review and migration planning. Frontend/API examples must match the canonical shared request protocol.
